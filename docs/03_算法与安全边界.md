# v0.4E-A 算法与安全边界

## 名称标准化

系统对名称执行：

- Unicode NFKC 统一；
- 英文字母大小写统一；
- 空格、横线、括号和常见标点移除；
- 机构名称可额外去除常见法定后缀后比较。

这些处理只用于匹配，不会改写主体标准名称。

## 重复评分

评分主要依据：

1. 标准化名称是否完全一致；
2. 去除机构后缀后是否一致；
3. 名称序列相似度；
4. 地区、类型、任职网络等字段是否一致。

人物同名风险较高。没有共同任职或组织网络证据时，即使姓名完全一致，也会限制评分，避免把不同人物误判为同一人。

## 本阶段不做的事情

v0.4E-A 不会：

- 自动选择保留主体；
- 自动迁移关系和业务引用；
- 自动停用重复主体；
- 自动删除主体；
- 自动合并事实版本；
- 把“高相似度”当成“同一主体”。

## v0.4E-B 才会处理

下一子阶段将在人工确认“同一主体”的基础上实现：

- 选择保留主体；
- 字段冲突逐项选择；
- 关系、项目、事件、资源、行动引用迁移；
- 审核与事实库主体编号迁移；
- 原编号重定向；
- 重复主体软停用；
- 合并预览、事务执行和回滚记录。
