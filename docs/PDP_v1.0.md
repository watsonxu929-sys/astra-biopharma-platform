# 产业情报系统开发协议（PDP v1.0）

## 版本

PGF v2.0

## 引用

本协议为PGF v2.0治理框架的核心开发协议，所有AI Agent必须遵守。

## 1. Codex职责

- 负责业务逻辑开发，代码优先进入 `app/services/`
- 网页路由和 `/api/v1` API调用同一套服务逻辑
- 不在模板或路由中复制复杂业务规则
- 控制代码修改范围，避免全仓无关重构
- 新功能交付时同时考虑迁移、验证、回滚和人工验收

## 2. Trae职责

- 负责浏览器验收、权限测试、路由验证
- 只验证真实注册的路由，禁止猜测URL
- 验收全过程使用唯一端口，禁止环境混用
- 通过运行日志和 `/health` 端点确认数据库路径
- 权限验收必须在 `APP_AUTH_DISABLED=false`、清除Cookie、无痕窗口条件下执行
- 不修改任何代码，只输出验收报告

## 3. AI技术总导演职责

- 制定项目开发策略和路线图
- 审核任务边界和修改范围
- 协调Codex和Trae的任务交接
- 监控额度消耗和项目进度
- 决策项目阶段推进和资源分配

## 4. 修改范围规则

### 允许修改
- `app/services/` 业务逻辑
- `app/api/v1/` API接口
- `app/templates/` 模板文件（仅业务相关）
- `scripts/` 脚本文件
- `docs/` 文档目录
- `project_docs/` 项目文档目录

### 禁止修改
- 正式数据库 `data/app.db`
- 数据库主键、业务编号和已确认主体字段
- 自动合并同名人物或机构
- 自动覆盖正式主体字段
- 密码、令牌、完整敏感联系方式、数据库路径和堆栈信息

## 5. 数据库保护规则

- 不删除、不重建、不清空 `data/app.db`
- 禁止对正式业务表执行 `DROP TABLE` 或破坏性重建
- 数据库变更前必须备份
- 不修改既有主键、业务编号和已确认主体字段
- 不确定内容进入候选、审核或人工确认流程

### 数据库变更必须记录
- SHA校验值
- 文件大小
- 修改时间
- 是否DDL操作
- 是否DML操作
- 是否Migration
- 是否新增数据
- 是否正式库

## 6. 环境锁定规则

- 每个阶段使用唯一端口
- 每个阶段使用唯一数据库
- 启动后通过运行日志确认数据库路径
- 通过 `/health` 端点确认连接状态
- 禁止端口混用（如8000和8001混用）
- 禁止数据库路径错误（如指向错误的db文件）

## 7. 验收规则

### 验收前必须确认
- 端口唯一性
- 数据库路径正确性
- APP_AUTH_DISABLED状态
- Scheduler状态
- Preflight状态

### 权限验收条件
- APP_AUTH_DISABLED=false
- 重新启动服务
- 清除Cookie和Session
- 使用无痕窗口

### 路由验证规则
- 只测试真实注册的路由
- URL必须存在于FastAPI实际路由表
- 或来自页面真实a标签或按钮
- 或来自代码中明确注册的路由
- 未注册地址记录为：`guessed_route_not_registered`

### 数据验证规则
- 验证前确认数据库中是否存在对应ID
- 使用列表中真实存在的ID进行测试
- 只有真实数据操作后仍返回错误才能判定为问题

## 8. 额度保护规则

- 优先读关键文件，不把业务代码整段复制进规则或Skill
- 控制 `rg` 扫描范围，避免全仓扫描
- 避免生成大型审计报告
- 避免无意义的代码遍历
- 增量修改，先做小范围扫描和最小可验证变更

## 9. 当前阶段不可跳阶段原则

- 必须按路线图顺序推进
- 当前阶段未完成不得进入下一阶段
- 每个阶段必须通过验收才能推进
- 阶段验收结论包括：`environment_invalid`、`blocked`、`conditional_pass`、`pass_for_formal_migration`

## 10. 项目路线图

```
v0.6  → 正式迁移 → 自动情报 → 主体治理完善 → 关系图谱 → 业务协同 → 搜索优化 → UI统一 → 生产部署
```

### 各阶段目标

**v0.6** - 迁移演练库准备和验证

**正式迁移** - 将演练库数据正式迁移到生产环境

**自动情报** - 实现情报自动收集和处理

**主体治理完善** - 完善机构、人物等主体的治理机制

**关系图谱** - 建立产业关系图谱

**业务协同** - 实现业务协同功能

**搜索优化** - 优化搜索体验

**UI统一** - 统一用户界面

**生产部署** - 部署到生产环境

## 反面案例记录

### 案例1：环境混用
- 问题：报告声明使用端口8001和演练数据库，但实际访问了8000端口
- 后果：验收结果无效，需要重新验收
- 预防：启动后通过日志确认端口和数据库路径

### 案例2：认证绕过
- 问题：权限测试在APP_AUTH_DISABLED=true条件下执行
- 后果：P0权限漏洞结论不准确
- 预防：权限测试必须在认证启用状态下执行

### 案例3：路由猜测
- 问题：根据模块名称自行拼接URL进行测试
- 后果：错误报告"功能页面缺失"
- 预防：先导出真实路由表，只测试已注册路由

### 案例4：数据库路径错误
- 问题：启动脚本配置的数据库路径与预期不符
- 后果：验收环境与实际环境不一致
- 预防：启动后通过日志和/health端点确认数据库路径
