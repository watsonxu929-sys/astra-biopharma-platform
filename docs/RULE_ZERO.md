# 零号规则

## 版本

PGF v2.0

## 最高原则

### 原则一：降低复杂度优先

**内容**：任何开发必须优先降低系统复杂度，而不是增加功能数量。

**说明**：
- 优先修复现有问题，而不是添加新功能
- 优先简化现有代码，而不是增加代码量
- 优先优化现有流程，而不是创建新流程

**违反后果**：任务将被暂停，重新评估开发方案。

### 原则二：阶段目标优先

**内容**：任何新功能不得破坏当前阶段目标。

**说明**：
- 当前阶段未完成不得引入下一阶段功能
- 新功能必须与当前阶段目标一致
- 不得为了未来功能而修改当前阶段代码

**违反后果**：任务将被暂停，功能将被回滚。

### 原则三：避免引入新复杂度

**内容**：不得为了修一个问题而引入新的复杂度。

**说明**：
- 修复问题的方案必须是最小变更
- 修复问题不得引入新的依赖
- 修复问题不得修改无关代码

**违反后果**：修复方案将被拒绝，重新设计。

## 原则优先级

零号规则的优先级高于所有其他规则和开发任务。

```
零号规则 > PGF v2.0治理框架 > 项目路线图 > 具体任务
```

## 违反处理流程

1. **发现违反**：任何Agent发现违反零号规则的行为
2. **报告**：向ChatGPT（AI Technical Director）报告
3. **评估**：评估违反的影响
4. **处理**：
   - 如果影响较小：暂停任务，修正方案
   - 如果影响较大：回滚变更，重新设计
5. **记录**：将处理过程记录到DECISION_LOG

## 执行指南

### 在开始任务前

- 评估任务是否会增加系统复杂度
- 评估任务是否与当前阶段目标一致
- 评估修复方案是否会引入新的复杂度

### 在执行任务中

- 随时检查是否违反零号规则
- 如果发现违反，立即暂停任务
- 重新设计方案

### 在完成任务后

- 验证任务是否增加了系统复杂度
- 验证任务是否与当前阶段目标一致
- 验证修复方案是否引入了新的复杂度
