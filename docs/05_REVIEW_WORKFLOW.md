# 05 Review Workflow

## 审核入口

页面：

```text
/review
```

健康检查：

```text
/review/health
```

## 自动识别类型

系统会把候选数据分为：

- 新增字段：正式事实库尚无该字段。
- 完全一致：候选值与当前正式事实相同，只追加来源证据。
- 正式事实冲突：候选值与当前正式事实不同。
- 候选间冲突：同一主体字段已有不同候选。
- 重复候选：合并到同一审核项并追加证据。
- 待确认关联：关系对象不能直接确认。
- 推测信息：只进入推测层，不直接成为事实。

## 单条审核

支持：

- 标记审核中。
- 通过。
- 驳回。
- 暂缓。

通过时可以填写最终采用值，并选择事实、推测或待判定。

## 批量审核

支持多选后批量：

- 审核中。
- 通过。
- 驳回。
- 暂缓。

批量操作使用事务处理，并为每条记录写入操作历史。

## 待确认关联

人物、主体、项目等关系在无法唯一确认时进入待确认关联。未审核或仍为推测的关联不得进入正式关系库。

## 审计历史

审核操作会保存：

- 审核前状态。
- 审核后状态。
- 原值、候选值、最终值。
- 操作人。
- 审核说明。
- 操作时间。
