# v0.4H 智能推荐与关系切入路径

## 目标

v0.4H 将现有线索、Q-BAY 会员供需、主体关系、资源和审核状态汇总为可解释推荐。所有结果均为内部候选建议，不会自动联系会员、自动建立正式关系或自动创建行动任务。

## 覆盖功能

- 推荐中心：`/recommendations`
- 关系路径查询：`/recommendations/path`
- 线索推进建议
- Q-BAY 会员供需候选匹配
- 企业/项目需求与会员资源联合匹配
- 高价值线索的数据风险提醒
- 三层以内的真实关系切入路径
- 采纳、拒绝、暂缓和恢复待处理
- 人工确认后转为行动任务
- 主体档案、线索详情和会员档案入口联动

## 安装

先备份项目文件夹，然后把补丁解压到项目根目录并覆盖同名文件。依次运行：

```bat
migrate_all_windows.bat
verify_all_windows.bat
run_windows.bat
```

迁移脚本会在 `data/backups/` 中创建数据库备份，不会删除或重建现有业务表。

## 首次使用

1. 确认系统中已有有效线索，或先在主体中心将企业/项目加入线索池。
2. 确认 Q-BAY 会员、需求和可提供资源已登记。
3. 确认人物—机构—项目关系已经人工核验。
4. 进入推荐中心，点击“刷新推荐”。
5. 打开推荐查看评分依据、风险和关系路径。
6. 人工选择采纳、拒绝或暂缓。
7. 确认需要执行时，再创建行动任务。

## 推荐类型

- 线索推进：综合线索评分、会员可达性、资源候选和数据风险。
- 会员供需：使用会员已登记的需求与供给生成候选匹配。
- 资源匹配：将企业/项目需求与会员供给进行规则匹配。
- 数据治理：提醒先处理会影响业务判断的审核或冲突。
- 关系切入：使用 `relations` 中的真实关系查找 Q-BAY 会员入口。

## 安全边界

- 不根据名称自动认定关系。
- 不自动合并同名主体。
- 候选供需匹配不等于正式合作关系。
- 最多查找三层关系，防止无限递归。
- 拒绝推荐必须填写原因。
- 同一推荐只能创建一次行动任务。
- 刷新推荐采用稳定键更新，不重复堆积相同候选。

## 回滚

代码回滚：恢复覆盖前的项目文件夹备份。

数据库回滚：仅在迁移后出现严重问题时，关闭后端，将 `data/backups/app_before_migrate_all_*.db` 或 `app_before_v04h_*.db` 复制回 `data/app.db`。回滚前请先另存当前数据库。
