# 正式同步与业务表映射

## 一、同步门槛

字段候选必须同时满足：

1. 审核状态为“已通过”；
2. 审核时显式选择“定为事实”；
3. 存在最终采用值，或使用候选值；
4. 尚未同步。

只“通过”但仍标记为“推测/待判定”的记录会显示为 `waiting_fact`，不会进入正式事实库。

## 二、正式事实库

默认同步目标是：

```text
v04c1_canonical_facts
```

它是 v0.4C-1 的正式事实层：

- 每个主体、字段只有一个当前版本；
- 新值通过后生成新版本；
- 旧值标记为 superseded，不删除；
- 保存来源审核项、来源记录、确认人和确认时间。

正式关联保存到：

```text
v04c1_canonical_relations
```

## 三、映射到现有业务表

在 `/review/intake` 的“业务表映射”中配置：

- 主体类型：如 `org`；
- 情报字段名：如 `临床阶段`；
- 目标表：如 `subjects`；
- 目标 ID 列：如 `id`；
- 目标字段列：如 `clinical_stage`；
- 目标名称列：可空；
- 是否允许目标不存在时自动新增；
- 是否启用。

建议默认：

- `允许新增`：关闭；
- `启用`：先关闭，核对后再启用。

系统通过候选的 `subject_id` 定位目标记录。没有 subject_id 时只写正式事实库，不更新业务表。

## 四、审计

所有同步结果写入：

```text
v04c1_sync_logs
```

包含目标位置、动作、成功/跳过/失败、更新前值、更新后值和错误原因。
