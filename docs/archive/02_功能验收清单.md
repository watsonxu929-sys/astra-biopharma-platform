# v0.4C 功能验收清单

逐项验证，全部通过才进入下一阶段。

## A. 页面与数据库

- [ ] `/review` 可以正常打开。
- [ ] 顶部能看到待审核、审核中、暂缓、已通过、已驳回数量。
- [ ] `/review/health` 返回 `"ok": true`。
- [ ] 原有企业、人物、项目、事件页面仍可打开。
- [ ] `data\app.db` 原有数据未丢失。

## B. 多来源冲突

- [ ] 新建一条“多来源冲突”。
- [ ] 查看证据时，不同来源各自独立显示。
- [ ] 追加新证据后，旧证据仍保留。
- [ ] 审核通过时可以填写“最终采用值”。
- [ ] 通过或驳回未填写说明时，系统会阻止提交。

## C. 待确认关联

- [ ] 新建“人物—创始人→企业”等关联。
- [ ] 新关联默认是“推测”和“待审核”。
- [ ] 确认后变为“事实”。
- [ ] 驳回后仍保留记录和说明，不物理删除。

## D. 批量审核

- [ ] 勾选多条审核项。
- [ ] 批量标记“审核中”可以成功。
- [ ] 批量通过/驳回要求填写统一说明。
- [ ] 查看单条详情时能看到批量审核留下的操作记录。

## E. 事实 / 推测分离

- [ ] 登记为“推测”的主张仍保持推测，不会自动变为事实。
- [ ] 登记为“事实陈述”的内容仍会进入审核队列。
- [ ] 临床阶段、金额、并购、处罚等高风险字段自动提升为高优先级。
- [ ] 来源等级和原文摘录能够保留。

## F. 回归验证

- [ ] 原来的 `self_check_windows.bat` 仍能通过。
- [ ] 关闭并重新启动后，审核数据仍存在。
- [ ] 同一条未结冲突重复提交时，不会生成重复审核项。
