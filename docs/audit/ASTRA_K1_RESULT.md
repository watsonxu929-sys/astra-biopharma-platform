## 用户入口和操作

1. 情报 → 产业知识 → 政策。知识管理人员右上角有“从资料建立知识”“知识更新待处理”；管理控制台的知识管理提供相同入口。
2. 现有Source详情/编辑 → 用于知识沉淀，选择已有Source、分类、政策范围及跟踪；仅复用该来源已有Collection/Snapshot证据，不要求先发布Intelligence，也不替用户启用Source。
3. 公开资料URL或上传DOCX、文字PDF、UTF-8 TXT/Markdown、HTML进入同一资料版本/拆解队列；新上传默认仅自己可见，已获准公开的资料需明确选择公开范围。
4. 首次在“采集与数据源”明确启用自动采集及资料处理；保留每个Source的启停/频率。资料勾选跟踪后才定期检查，上传文件通过“上传新版”更新。三个正式示范资料均未自动启用跟踪。
5. 同一预览页可改标题/分类、合并相邻候选、按原句拆分、忽略、批量确认。默认形成草稿；“明确确认并发布/更新”是独立动作。改变更新目标必须先保存并重新查看差异。
6. 政策字段可在资料页一次核对后应用于待审候选，正式知识不随之改变。正式政策修改走现有知识编辑；效力与文件关系必须提供依据。R3日期建议与正式确认分开，未知日期留空，采集时间不代替发布时间。

## 明确限制与文件范围

- 分类是可回看的确定性规则/来源配置，不是AI；无法确认的留待分类。跨章节条件和复杂表格必须核对、必要时合并；结构候选不是经认证的政策判断。页面来源日期只能作为建议，正式效力不自动认定。
- 不支持扫描OCR、加密PDF、宏执行、外部嵌入对象；8MB文件、200页PDF、32MB DOCX解包、200结构段限制。PDF使用固定版本pypdf 6.19.0（BSD-3-Clause，轻量离线依赖）。
