# v0.4D-A 故障排查

## 1. `/review/structure` 显示 404

检查 `app/main.py` 是否同时存在：

```python
from app.v04d_structuring import router as v04d_structuring_router
```

以及：

```python
app.include_router(v04d_structuring_router)
```

保存后停止并重新启动后端。

## 2. 启动时报 `ModuleNotFoundError: app.v04d_structuring`

确认文件位置是：

```text
项目根目录/app/v04d_structuring.py
```

而不是：

```text
项目根目录/v04d_patch/app/v04d_structuring.py
```

## 3. 页面报模板不存在

确认：

```text
app/templates/v04d_structuring.html
```

已复制到现有模板目录。

## 4. 迁移或验证脚本闪退

使用本补丁中的 `.cmd` 文件，不要改为旧版 LF 换行的批处理文件。

也可以在项目根目录的 VS Code 终端执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\migrate_v04d.py
.\.venv\Scripts\python.exe -X utf8 scripts\verify_v04d.py
```

日志位于：

```text
logs/v04d_migrate.log
logs/v04d_verify.log
```

## 5. 页面没有待结构化来源

可以：

1. 从“原始情报库”直接点击“开始结构化”；
2. 在 `/review/intake` 从 `raw_intelligence` 导入；
3. 运行一次 `seed_v04d_demo_windows.cmd`。

## 6. 不能提交结构化复核

页面底部会列出校验问题。常见原因：

- 没有添加任何条目；
- 没有绑定证据摘录；
- 字段候选缺少主体、字段名或候选值；
- 关系候选缺少左右主体；
- 事件候选缺少事件名称或摘要。

## 7. 关系明明选择“事实”，送审后仍是推测

这是安全设计。自动或人工整理出来的关系先进入待确认关联，必须在 v0.4C 中再次人工确认，避免错误关系直接成为事实。

## 8. 事件为什么生成多条审核项

事件被拆分为可独立核验的字段，例如：

- 事件名称；
- 事件日期；
- 事件类型；
- 相关主体；
- 事件摘要。

这样可以分别比较来源、处理日期冲突，并保留完整审计记录。

## 9. `database is locked`

1. 先关闭重复启动的后端窗口；
2. 不要同时运行多个迁移或演示脚本；
3. 等待数秒后重试；
4. 检查任务管理器中是否存在多个 Python/Uvicorn 进程。

本模块沿用 v0.4C 的 WAL、busy timeout 和分段事务设计。
