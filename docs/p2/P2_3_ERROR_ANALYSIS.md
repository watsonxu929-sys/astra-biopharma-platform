# P2.3 验证与误差分析

## 已验证

- P2.3 定向测试：9/9 通过；全量 pytest 共 56 项，55 通过、1 跳过。
- 005 在数据库副本连续执行两次，第二次无缺表/缺列，具备幂等性。
- 受控试点产生 3 个双来源事件、1 个模拟冲突和 1 份引用完整率 100% 的草稿。
- 数据库副本上的专题列表、工作区、时间线、事件、冲突、发现、企业/赛道对比、报告审核页和 API 工作区均 HTTP 200。
- 正式库中不存在任何 `p2_3_*` 表，ResearchTopic 为 0，正式报告原有 1 条；试点未迁移正式库。

## 已知误差与限制

1. 事件融合是首版确定性评分，不包含向量检索；同义产品名和复杂企业别名仍需人工判断。
2. 试点只有 FDA 两份文档、3 个事件，不能代表所有来源类型或语言。
3. 模拟冲突用于验收工作流，不可作为真实业务冲突结论。
4. 三家试点企业在副本中临时建立并有明显来源标记，尚未执行正式主体匹配。
5. 赛道政策影响、核心团队等无可靠数据时明确返回“暂无可靠数据”。
6. 模板全量检查 82 个模板中 73 个通过；9 个既有 platform 模板缺少 `status_label` 过滤器，非 P2.3 引入，未在本任务扩修。
7. 任务起始记录的正式库 SHA256 为 `4b7a2d2eee9e6d7a2936af986a2396bdfbf15922b7cacdca3ee36166740b30fc`，结束检查为 `a182f3b660c30908103e9f61ffdd8658aa5e9db3eb020d0ccc481e2bdebecbf8`。正式库无 P2.3 表且业务计数未增加；现有 `db_connection` 会执行 `PRAGMA journal_mode=WAL`，文件头/旁路文件可能发生物理变化。该差异仍登记为待人工核验，不能表述为“前后 SHA 一致”。
