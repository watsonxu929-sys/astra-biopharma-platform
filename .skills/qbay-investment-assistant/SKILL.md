# Q-BAY 企业招商研判 Skill

## 版本与定位

- 版本：2.0.0
- 维护对象：Q-BAY产业情报与招商运营
- 建议复核周期：每季度
- 核心原则：**事实、判断、建议分离；所有结论可追溯；不因用户期待而拔高评级。**

本 Skill 用于将企业公开信息转化为可审核的招商研判结果，并与产业情报系统中的企业、人物、事件、关系、线索、推荐和行动模块衔接。

## 何时使用

当任务明确涉及下列任一内容时使用：

- 企业招商评估或招引可能性判断；
- 判断企业是否适合进入上海 Q-BAY 孵化器；
- 判断企业是否适合杭州钱塘区租赁载体或拿地自建；
- 对企业进行招商 A/B/C/D 评级；
- 筛选招商名单、更新招商台账或批量研判；
- 从企业动态中识别融资、扩产、选址、迁址、合作、临床、产品、招聘等招商信号；
- 形成招商行动建议、关系切入口或跟进优先级。

## 何时不使用

以下任务不要自动调用本 Skill：

- 普通企业介绍、宣传文案或新闻摘要；
- 仅查询创始人、地址、电话等单一事实；
- 无招商目的的企业研究；
- 投资买卖建议、证券评级或信用评级；
- 对个人作背景调查；
- 无公开来源支撑的主观判断。

若用户只给企业名称但未说明招商目的，应先确认是否需要招商研判；若上下文明显属于招商项目，可直接执行。

## 输入要求

最少输入：

- 企业名称；
- 研判目标：Q-BAY、钱塘区或双维度；
- 可选：统一社会信用代码、官网、已知联系人、当前名单字段、用户已有备注。

批量任务还应提供：

- 企业清单；
- 是否允许联网检索；
- 是否已有人工字段不可覆盖；
- 输出格式：自然语言、JSON、CSV/Excel增量更新或系统写入建议。

## 必须读取的参考文件

执行前按需读取：

- `references/regional-classification.md`
- `references/scoring-rules.md`
- `references/source-quality.md`
- `references/track-definitions.md`
- `references/system-mapping.md`
- `templates/output-schema.json`

涉及批量输出时，使用 `scripts/validate_output.py` 校验结构化结果。

# 标准执行流程

## 第1步：确认企业身份

优先确认：

1. 企业正式名称；
2. 曾用名、简称、英文名；
3. 注册地和主要经营地；
4. 官网和统一社会信用代码；
5. 母公司、子公司或品牌关系。

若存在多个同名主体，不得自行选择。输出候选并要求人工确认。

## 第2步：地域分类

按 `references/regional-classification.md` 分类：

- 上海本地型；
- 浙江省内型；
- 长三角其他地区型；
- 长三角外异地型；
- 钱塘/Q-BAY本地资源型。

本地资源型使用 `R`（Resource）标记，不参与 A/B/C/D 招商等级，避免把“本地资源价值”误判为“低质量企业”。

## 第3步：赛道与企业类型

按 `references/track-definitions.md` 判断：

- 主赛道；
- 交叉赛道；
- 优先级；
- 企业类型：外部融资驱动、自我滚动发展、子公司/关联公司。

完全不在目标赛道范围时，标记 `OUT_OF_SCOPE`，除非用户明确要求继续研判。

## 第4步：公开信息检索

按以下优先级检索并记录证据：

1. 企业官网、政府官网、交易所公告、药监/临床登记等官方来源；
2. 投资机构官网、上市公司公告、权威行业数据库；
3. 权威财经和产业媒体；
4. 招聘平台、行业媒体、自媒体和转载内容。

至少覆盖：

- 工商与主体信息；
- 融资与股东背景；
- 扩产、迁址、选址、招聘和环评；
- 产品、管线、临床、专利和商业化进展；
- 荣誉资质；
- 政策支持与本地绑定；
- 浙江/上海资本、产业链和活动关联；
- 公开联系人或关系切口。

每条重要结论记录：

- 来源标题；
- 来源 URL；
- 发布时间；
- 抓取时间；
- 来源等级；
- 证据摘录；
- 支持的事实字段。

未检索到时明确写“未检索到”，不得补写。

## 第5步：事实、判断、建议分离

所有输出按三层组织：

### 事实

仅陈述公开来源能够证明的内容。

### 系统判断

说明该事实为何构成：

- 发展信号；
- 招商窗口；
- 匹配因素；
- 招引阻力；
- 关系切入口；
- 数据缺口。

### 招商建议

给出具体行动，包括：

- 联系谁；
- 通过什么关系切入；
- 需要补充什么信息；
- 是否适合Q-BAY；
- 是否适合钱塘区租赁；
- 是否适合钱塘区拿地；
- 建议跟进时限。

## 第6步：评分与分级

使用 `references/scoring-rules.md` 中的100分模型：

- 赛道匹配：0—20；
- 发展信号：0—25；
- 空间/载体匹配：0—20；
- 窗口期：0—15；
- 关系可达性：0—10；
- 信息完整度：0—10；
- 招引阻力：0至-30。

等级：

- A：80—100；
- B：65—79；
- C：45—64；
- D：0—44；
- R：钱塘/Q-BAY本地资源型，不参与招商评级；
- OUT_OF_SCOPE：不在目标赛道或招商范围；
- UNVERIFIED：信息不足，无法形成有效评级。

硬性校正规则优先于分数，例如：

- 已明确落地其他园区且排他性强：最高D；
- 获得所在地土地或重大绑定支持：至少降一档；
- 外资决策权在境外且无华东扩张证据：最高C；
- 信息严重不足：UNVERIFIED，不用D掩盖信息缺口；
- 本地资源型：R，不使用D。

每次评级必须输出分项得分、扣分项和硬性校正。

## 第7步：双维度招商建议

### 上海 Q-BAY 孵化器

重点判断：

- 是否处于早期研发或轻资产阶段；
- 是否需要上海研发空间、产业资源或快速入驻；
- 人员和空间规模是否匹配孵化器；
- 是否需要投融资、研发平台或BD资源。

不适配时明确写“该维度暂不适配”。

### 杭州钱塘区

分别判断：

- 园区载体租赁；
- 工业用地/厂房购置或自建。

重点判断：

- 是否有华东第二基地意向；
- 是否有产能、空间、成本或产业化需求；
- 是否已有浙江资本、客户、供应链或政府关系；
- 是否存在明确决策窗口。

早期纯研发企业不应勉强推荐拿地。

## 第8步：系统映射

按 `references/system-mapping.md` 将结果映射为系统建议：

- 企业事实 → Organization；
- 人物和联系人 → Person；
- 融资、合作、扩产等 → Event；
- 招商信号 → Signal；
- 招商评级 → LeadRecord/招商评估；
- 关系线索 → RelationshipCandidate；
- 行动建议 → Recommendation；
- 人工确认后的跟进 → Action；
- 来源 → SourceRecord/Snapshot。

未经人工确认，不得自动创建正式关系、行动或覆盖主体字段。

# 单企业输出要求

必须同时输出：

1. 企业速览；
2. 事实清单及来源；
3. 地域、赛道和企业类型判断；
4. 评分明细；
5. 等级及校正原因；
6. Q-BAY适配建议；
7. 钱塘区租赁适配建议；
8. 钱塘区拿地适配建议；
9. 关系切入口；
10. 建议行动和时限；
11. 数据缺口；
12. 结构化JSON结果。

自然语言报告不能替代JSON结果。

# 批量任务要求

- 先确认列映射和不可覆盖字段；
- 只更新有变化的字段；
- 人工备注、电话记录、最近跟进不得覆盖；
- 同名企业先核验身份；
- 信息不足标记UNVERIFIED；
- 本地资源型标记R；
- 批量任务要输出成功、跳过、待核验和失败数量；
- 使用 `scripts/validate_output.py` 校验每条结果；
- 输出汇总，不逐条重复整篇报告。

# 安全和质量规则

必须遵守：

- 不编造融资、政策、人员、客户、产能和迁移意愿；
- 不把荣誉资质等同于迁移意愿；
- 不把政府深度扶持当作纯正面信号；
- 不将同名企业或人物自动合并；
- 不将招商等级解释为企业质量或信用评级；
- 不提供证券投资买卖建议；
- 不记录或传播非公开私人信息；
- 对冲突来源并列展示，不擅自选择有利结论；
- 结论超过来源证据时，必须标记为“推断”；
- 信息不足时停止拔高，转为补充调查建议。

# 失败处理

出现以下情况时停止自动评级：

- 企业身份无法确认；
- 同名主体无法区分；
- 核心来源相互冲突；
- 主要信息均来自低质量转载；
- 无法判断企业主营业务；
- 缺少必要的招商目标信息。

输出：

- 已确认事实；
- 未确认点；
- 需要用户提供的材料；
- 下一步检索建议；
- 状态 `UNVERIFIED`。

# 完成回执格式

每次任务完成后，简要说明：

- 研判企业数量；
- A/B/C/D/R/OUT_OF_SCOPE/UNVERIFIED分布；
- 关键招商机会；
- 主要招引阻力；
- 需人工核实数量；
- 结构化结果是否通过校验；
- 是否生成系统写入建议；
- 未完成事项。
